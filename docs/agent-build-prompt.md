# Claude Code 実行用プロンプト：URL入力型・生成AI活用提案書 自動生成エージェント

> 本ドキュメントは、経営コンサルティング事業における「潜在顧客への生成AI活用提案書」を自動生成するエージェントを、Claude Codeに構築させるためのプロンプトです。以下の内容をそのままClaude Codeに指示として渡してください。

---

## あなたの役割

あなたは、経営コンサルティングファーム向けの提案書自動生成ツールを開発するシニアエンジニアです。本リポジトリ（Streamlit製「FASTLabel 提案書作成ツール」）を拡張し、下記要件を満たす機能を実装してください。

## 背景（現状のコードベース）

現在の `app.py` は、ユーザーが**企業名**を入力すると、

1. `utils/web_search.py` — Claudeの組み込みWeb検索で企業情報を調査
2. `utils/rag.py` — FASTLabel社内資料（PDF/DOCX/PPTX/TXT）をRAG参照
3. `utils/proposal_generator.py` — Claudeで課題仮説・提案内容を生成
4. `utils/pptx_creator.py` — 10枚構成のPowerPointを出力

という4ステップの生成フローを持つStreamlitアプリです。

## 目的

生成AI活用に関する潜在顧客ニーズが急拡大している中、営業の初動を高速化するため、**潜在顧客のWebサイトURLを入力するだけ**で、その企業の実態に即した「生成AI活用提案書」をパワーポイント形式で自動生成できるようにする。

## 機能要件

### 1. 入力

- **潜在顧客のWebサイトURL**（コーポレートサイトのトップページ等）を主入力とする。企業名は任意の補足入力欄として残してよい。
- URLからコーポレートサイトの主要ページ（会社概要／事業内容／IR情報／ニュース・プレスリリース／採用ページ等、たどれる範囲で）を取得し、加えてWeb検索で業界動向・競合・直近ニュースなど補完情報を収集すること。
- 既存の「FASTLabel社内資料RAG」「APIキー入力」「資料アップロード」機能は維持する。

### 2. 出力

- PowerPoint形式（`.pptx`）の提案書。ファイル名に企業名を含める。

### 3. アウトプットに含める内容（スライド構成）

以下を基本構成とし、目的に資する範囲で項目の追加・統合・順序変更を検討してよい。

1. 表紙
2. アジェンダ
3. **企業概要** — 事業ドメイン、規模、沿革・直近のトピック等、収集した事実ベースの情報
4. **主要事業** — 事業セグメントごとの整理
5. **主要事業における課題仮説** — 一般論ではなく、収集した事実・業界動向から論理的に導かれる、その企業固有の課題仮説。セグメントごとに紐づけること
6. 生成AI活用の全体観（なぜ「今」「この企業」にとって有効かの説明）
7. **生成AI活用アプローチ案** — 上記の課題仮説それぞれに対応する具体的なユースケース（2〜3件）
8. 各アプローチの詳細（提供価値／差別化ポイント／期待効果）
9. **計画・導入の進め方案** — フェーズ分けしたロードマップ（現状診断→PoC→本導入→展開）、推進体制案、想定期間・マイルストーン
10. 想定投資規模・ROI試算（既存のON/OFFオプションを維持）
11. 想定される論点・Q&A（初回ディスカッションで経営者から出そうな質問と回答の想定）
12. 次のステップ（Next Actions）
13. Appendix：リサーチサマリーと出典（参照したURL・情報源を明記し、根拠の透明性を担保）

### 4. 品質要件（最重要）

提案先は潜在顧客の**経営者**であり、アウトプットは**初回議論に耐える水準**でなければならない。一般的な生成AI活用の解説で終わらせず、以下を徹底する。

- 収集した企業固有の事実（事業内容、規模、業界内ポジション、直近の取り組み・ニュース等）を根拠として明示し、それに直接紐づく課題仮説・アプローチ案にすること。
- 「業務効率化」「DX推進」のような抽象的な一般論だけで終わらせない。具体的な業務プロセス名・部門名・想定KPIまで踏み込ませる。
- 経営者が「自社のことを事前にきちんと調べている」と感じられる固有名詞（製品名、事業拠点、直近のニュース・IR情報等）を本文中に盛り込ませる。
- 生成AIアプローチは、コンサルティングファームとして実際に提供できる支援内容（現状診断、PoC設計、内製化支援、伴走支援等）と紐づけて記述させる。
- 課題仮説・アプローチ案の生成プロンプトでは、根拠事実を先に列挙させてから結論を書かせる（事実→示唆→提案の順で思考させる）よう設計すること。

## 技術方針

### 変更対象ファイル

- `app.py` — 入力フォームを「企業名」から「企業URL（企業名は任意併記）」に変更。生成フローの表示文言・進捗表示を更新。
- `utils/web_search.py` — URLを起点としたサイト情報取得ロジックを追加（`requests` + `BeautifulSoup`等でのページ取得、または Claude の Web fetch／検索ツールとの併用）。既存の企業名ベース検索関数は、URL起点のリサーチ処理に置き換えるか、事業環境・業界動向の補完取得として残す。
- `utils/proposal_generator.py` — プロンプトと出力スキーマを新しいスライド構成に合わせて拡張する（課題仮説とアプローチ案の1:1対応、Q&A想定、リサーチ根拠の保持など）。
- `utils/pptx_creator.py` — 新しいスライド構成・レイアウトに対応させる。
- `requirements.txt` — URL取得に必要なライブラリ（例：`requests`, `beautifulsoup4`）を追加。
- `README.md` — 新しい入力方式・使い方に合わせて更新。

### 非機能要件

- 不正なURL、アクセス不可（404／タイムアウト／取得制限等）に対するエラーハンドリングと、ユーザーに分かりやすいメッセージ表示。
- サイト取得・解析に時間がかかる場合の進捗表示（既存の `st.progress` パターンを踏襲）。
- 公開ページの範囲内での情報取得に留め、不要な個人情報・非公開情報を収集しない。
- 既存のAPIキー管理・Docker構成・RAG機能との後方互換性を維持する。

## 検証方法

- ローカルで `streamlit run app.py` を起動し、実在する企業のWebサイトURLを入力して一連の生成フローが完走することを確認する。
- 生成された `.pptx` をPowerPoint等で開き、レイアウト崩れがないことを確認する。
- 生成内容が入力企業固有の情報に基づいているか（一般論に留まっていないか）を目視でレビューする。

## 完了条件（Definition of Done）

- WebサイトURLを入力するだけで、上記スライド構成の提案書（`.pptx`）が生成される。
- 課題仮説・アプローチ案が入力企業に具体的に紐づいた内容になっている（一般論のテンプレートになっていない）。
- 既存機能（社内資料RAG、ROI/事例スライドのON/OFF、APIキー管理）が壊れていない。
- `README.md` が新仕様に更新されている。
- 変更内容をコミットし、指定ブランチにプッシュする。
